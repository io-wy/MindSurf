## 3. 模型与训练配方

| 配置项 | 数值 |
| --- | ---: |
| 参数量 | 89,864,448 |
| Hidden size / layers | 768 / 8 |
| Attention heads / KV heads | 8 / 8 |
| FFN size | 3,584 |
| Vocabulary | 6,400 |
| Sequence length / batch size | 384 / 32 |
| 完成 optimizer steps | 168,000 |
| Seen tokens | 2,064,384,000 |
| Learning rate | `5e-4`，AdamW betas `(0.9, 0.95)`，weight decay `0.01` |
| Schedule | WSD：warmup 200 + stable 80% + cosine decay，min_lr_ratio 0.1 |
| 精度 | bfloat16 autocast，RMSNorm 均方归约上溯 float32 |
| 计算预算标尺 | 约 23 tokens/参数（计算最优约 20） |

结构：RoPE（theta 1e6）、QK RMSNorm、MHA、SwiGLU、权重绑定。

数据处理链（各阶段产物均有独立 SHA-256 与 manifest 继承链）：
原始文本 → NFKC 归一与空白折叠 → 质量过滤 → 安全/PII → MinHash 近似去重 →
**全局置换打散** → 预分词 memmap → 流式加载。全量去重命中 444,897 条（5.26%），
PII 命中 8,739 行，总丢弃 5.44%；预分词产出 5,500,556 块 = 2.117B tokens。
训练视图 SHA-256 `4222e9ca19e8e2e369beee41dd00594ee87eb8d9b946738c16854506f1da47a2`。

参照系是历史最优候选 shuf60k seed20260721，**用当前管线重评**后取值。

两 seed 的实测差（仅扰动初始化，见 §5）：strict_val 0.0020、strict_test 0.0031、
六项 domain 0.0003–0.0051、`generation_health.degenerate_count` 0。门控余量
+0.10~+0.17 nats 是该差值的 7–12 倍。

**可作能力表述的结论**：相对历史最优参照，本候选在同分布 strict holdout 与全部
六项 domain 切片上**改善**，效应量远超噪声底；固定长度贪心生成
**100 条探针零退化**。

**不可作能力表述的**：MCQ 准确率与旧版 repetition 计数。MCQ v2 已被用户审核判定
不一致且功效不足（192 题极限 ±7pp，关心效应 3–5pp，物理上分不出），旧版
repetition 早停免检且 n=10。两者只记录，不支撑任何"更强/更弱"的说法。

生成健康仪器本身的效度证据：固定生成长度（`eos_token_id=None` 消早停免检）、
100 条独立主题探针（零模板繁殖）、脚本中立统计量 `top_bigram_mass`，四项干预
测试（消早停/消长度/消格式/分语种）全过，6 项单元测试在库。

## 5. 已知限定（与权重一同登记，不得省略）

1. **实际训练 168,000 步而非计划的 172,000**。172k 预算比预分词视图多要了 107
   步（5,500,556 blocks ÷ batch 32 = 171,892 步上限），加载器只在取空时报错，
   于是单 epoch 跑到最末尾才暴露。step-168000 的 rolling checkpoint 完整，覆盖
   该 epoch 的 97.7%，且已越过 WSD 退火起点 137,640。已加护栏：`train.py` 构造
   数据集后立即比对所需 block 与容量，超出即拒并给出最大可承受步数。
2. **双 seed 只扰动初始化**。`PackedBlockDataset` 顺序读且拒绝 `shuffle_buffer`，
   两 seed 的数据顺序完全相同。语料已在预分词前全局打散，两 seed 覆盖同一 97.7%
   语料。因此两 seed 差值是噪声底的**下界**，不是估计值，据此得出的结论强度相应
   降级。未做的改进：按 seed 生成块索引置换（随机访问，成本极低），可让未来 run
   天然满足双 seed 要求。**不为此重跑 7 小时**是有据的取舍，不是疏漏。
3. **`training_summary.json` 由 checkpoint 反推**（`scripts/summarize_checkpoint.py`），
   不是训练结束时写出的——run 在写摘要前就因 §5.1 死掉了。摘要字段全部取自
   checkpoint 的 `progress` 块，文件内 `derived_from_checkpoint` 字段标明来源。
4. **外部锚点**（§1 四支柱之一）见 §7 状态。
5. **下游可用性**由 SFT 阶段回流验证，本阶段不自证、不虚报。

### 8.1 外部锚点 — **未成立（作废），如实降级为三支柱**

上游官方预训练 checkpoint（ModelScope `gongjy/MiniMind2-PyTorch` 的
`pretrain_512.pth` 26M 档与 `pretrain_768.pth` 104M 档）已取得并成功移植——移植
逐位忠实，对上游自己的模型代码最大绝对 logit 差 **0.0**。但锚点仍然作废，原因是
一个可量化的事实：**这批权重训练所用的 tokenizer 与本项目的不是同一个**
（`d98595c6…` 对 `71f32c68…`），同为 6,400 词表但 1,772 个 token 互不存在、
4,619 个 id 不同。用本项目 tokenizer 评测，两个锚点的 loss 是 12.5733 / 12.0227，
而 6,400 词表均匀猜测是 8.7641——**比随机还差**，即 token id 含义已错位。

如果没有 tokenizer 闸门，这次评测会打印出"本项目 89M 完胜上游 104M 十个 nats"，
而这个优势完全由错配制造。因此**不报告任何方向的比较**，锚点标注为未成立。
完整证据、确立方式与取舍见
[外部锚点：端口成立，锚点作废](../experiments/2026-07-22-external-anchor.md)
与 `artifacts/evaluation/anchor_upstream_void.json`。

**未取得证据的支柱一律标注为未成立，不以其他支柱代偿。** 因此本发布**不含任何
依赖外部锚点的能力表述**：§4 与 §8.2 的结论全部相对本项目历史最优参照，属于内部
纵向比较，其局限——参照系是自家模型，因而无法排除整条管线共有的系统性偏差——在此
明示。上游若发布基于当前 tokenizer 训练的权重，锚点是一条命令的事，端口与闸门
已在库（`scripts/evaluate_external_anchor.py`，9 项测试）。
